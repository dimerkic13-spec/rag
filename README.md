# RAG-бот для технической документации

Цель проекта — создать русскоязычного помощника для работы с руководствами трёх программных продуктов. Пользователь задаёт вопрос в веб-чате и получает ответ со ссылкой на документ, его версию и страницу. Если в документации нет подтверждения, бот сообщает об этом.

**Статус проекта:** подготовлено техническое задание. Ниже описаны требования к первой версии и порядок проверки решения.

## Как будет работать бот

Около 30 PDF-руководств будут распределены по трём базам знаний или логически разделённым разделам. При загрузке система извлечёт текст и таблицы, разобьёт материал на фрагменты и сохранит для каждого продукт, версию, документ и номер страницы.

Пользователь сможет выбрать продукт или выполнить общий поиск. По запросу система найдёт фрагменты с учётом технических терминов, аббревиатур и названий функций. Модель сформирует ответ только по найденным источникам с учётом версии продукта. При выходе нового руководства документацию можно будет обновить без полной пересборки системы.

## Планируемые компоненты

| Компонент | Назначение |
| --- | --- |
| Dify Self-hosted | Загрузка документов, настройка поиска и встроенный веб-чат |
| GigaChat Embeddings | Получение векторных представлений фрагментов и запросов |
| Platform V Vector DB | Хранение векторов и поиск фрагментов с фильтрацией по метаданным |
| GigaChat API | Генерация ответа на русском языке по найденным фрагментам |
| Российская PostgreSQL-совместимая СУБД | Хранение системных данных и метаданных Dify |

Развёртывание планируется на сервере организации или в согласованной российской инфраструктуре. До выбора рабочей конфигурации предстоит согласовать использование Dify и проверить совместимость конкретных версий компонентов.

## Этапы и критерии готовности

1. **Проверить интеграции.** Из Dify выполнить генерацию ответа и запрос эмбеддингов, проверить запись и поиск с фильтрами в Platform V и применение миграций в выбранной СУБД.
2. **Провести пилот на одном продукте.** Загрузить один PDF и сверить ответы с текстом и номерами страниц руководства. Особое внимание уделить таблицам, номерам страниц и вопросам, на которые в руководстве нет ответа.
3. **Подключить остальные продукты.** Загрузить согласованный комплект документов, проверить выбор продукта, общий поиск и корректность ссылок при наличии разных версий руководства.
4. **Автоматизировать приёмку.** Подготовить минимум 150 контрольных вопросов с эталонами, запускать проверки через API Dify и формировать отчёт о качестве поиска, ответов, ссылок и обоснованных отказов.
5. **Подготовить эксплуатацию.** Настроить журналирование запросов и ошибок, проверить восстановление из резервной копии и передать инструкции пользователю и администратору, включая порядок обновления документов.

## Рабочее место и первое упражнение

В облачном Codex откройте терминал в каталоге `/workspace/rag`. Для работы на своём компьютере клонируйте репозиторий командой `git clone https://github.com/dimerkic13-spec/rag.git` и перейдите в `rag`. Команды ниже рассчитаны на Bash и Python 3. Для проверки реестра достаточно стандартной библиотеки Python.

1. Проверьте учебный пример командой `python3 scripts/check_registry.py examples/documents.csv`. Ожидаемый вывод — «Реестр проверен. Записей: 1».
2. Создайте личную копию шаблона командами `mkdir -p data` и `cp -n examples/documents.csv data/documents.csv`. В текущем облачном рабочем каталоге копия уже подготовлена. Каталог `data/` исключён из Git.
3. Выберите один PDF по одному продукту. В `data/documents.csv` замените учебную строку записью о выбранном руководстве. Укажите продукт, версию, название и имя PDF. Сохраните CSV в UTF-8 с запятой в качестве разделителя.
4. Выполните `python3 scripts/check_registry.py data/documents.csv` и убедитесь, что реестр содержит одну запись. Скрипт проверяет структуру реестра, заполнение полей, расширения имён и повторы. Содержимое PDF предстоит проверить при загрузке в Dify.
