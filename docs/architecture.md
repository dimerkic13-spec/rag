# Предварительная архитектура RAG

Пилот использует документацию одного продукта в одном PDF. Ответ должен опираться на найденные материалы и указывать документ, версию и страницу. При недостатке подтверждений бот сообщает, что ответа в документации недостаточно.

## Обработка документов

`src/ingestion/` предназначен для извлечения текста и таблиц из PDF и разбиения материалов на фрагменты. Для каждого фрагмента потребуется сохранить идентификатор продукта, версию, документ и номер страницы. Локальные исходники, результаты обработки и реестр предусмотрены в `data/raw/`, `data/processed/` и `data/registry/`.

## Поиск

`src/retrieval/` предназначен для поиска фрагментов по вопросу и фильтрации по продукту и версии. Кандидат для векторизации документов и запросов — GigaChat Embeddings. Для хранения и поиска векторов рассматриваются Qdrant и Platform V Vector DB. При переходе к трём продуктам и примерно 30 PDF метаданные позволят искать по одному продукту или по всему согласованному корпусу.

## Генерация

Предварительный вариант — Dify для оркестрации и веб-чата, GigaChat для генерации ответа по найденным фрагментам. `src/integrations/` предусмотрен для адаптеров внешних систем, `infra/dify/` — для будущей конфигурации платформы.

## Совместимость и проверки

Связки Dify с GigaChat, GigaChat Embeddings и кандидатами векторной БД пока не проверены. Выбор версий и совместимость зависимостей с Python 3.13 предстоит проверить в RAG-004. Автоматизированная приёмка должна проверять качество поиска, корректность ссылок, соответствие ответов источникам и отказы при недостатке данных.
