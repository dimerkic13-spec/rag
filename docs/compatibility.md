# RAG-004. Совместимость технологий

Проверки ведутся по известным требованиям проекта. Формальные критерии, целевые версии и пороги качества нужно сверить с утверждённым ТЗ, когда оно появится в репозитории.

| Компонент | Что подтверждено | Проверка в целевой среде |
| --- | --- | --- |
| Python 3.13 | Python 3.13.5 запустил валидатор и модульные тесты в виртуальном Linux | Запустить те же проверки в Windows 11 / WSL 2, отдельно проверить зависимости выбранных версий |
| Docker Desktop и WSL 2 | В облачном Linux доступен клиент Docker. Доступ к демону запрещён, WSL 2 недоступна | Проверить `wsl --status`, `docker version` и `docker compose version` на целевой машине |
| Dify | Предварительный кандидат. Рабочий экземпляр и ключ API отсутствуют | Проверить выбранную версию, модельный адаптер, конфигурацию БД и режим цитирования |
| GigaChat и GigaChat Embeddings | Методы описаны в документации поставщика. Учётные данные в среде отсутствуют | Выполнить авторизованные запросы генерации и эмбеддингов на синтетических данных. Зафиксировать версии моделей и размерность эмбеддингов |
| Platform V Vector DB | Поставщик указывает регистрацию продукта в российском реестре и происхождение от Qdrant | Получить согласованный экземпляр и проверить версию, запись, поиск с фильтрами и пригодность применяемых алгоритмов по ТЗ |
| Системная СУБД Dify | Конкретная российская СУБД пока не утверждена | Проверить миграции Dify, резервное копирование и восстановление на выбранной версии |

Действует ограничение на российские алгоритмы и базы данных. Регистрация дистрибутива Platform V сама по себе не подтверждает происхождение каждого алгоритма. Поставка Qdrant отдельно остаётся вне конфигурации до подтверждения соответствия. Модели, алгоритмы и БД в рамках этой проверки не подключались, документы не передавались сервисам.

## Последовательность проверок

1. Зафиксировать согласованные версии и доступность целевой среды.
2. Проверить генерацию, эмбеддинги, запись и поиск с фильтрами по продукту и версии, затем миграции системной БД. Использовать синтетические данные.
3. Проверить пилотный корпус с одним PDF. Для ответа проверить ссылку на правильный документ и физическую страницу PDF. Для вопроса без подтверждения проверить явное сообщение о недостатке сведений.
4. После получения согласованного комплекта документов проверить изоляцию трёх продуктов и общий поиск. Утвердить набор контрольных вопросов, критерии и график регулярной приёмки. Офлайн-проверка реестра не оценивает качество ответов.
