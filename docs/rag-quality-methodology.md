# Оценка пилота

Источник — инструкция Windows, шифр ЖТЯИ.00101-04 92 01, версия 5.0 R4 KC1. В JSON находятся 50 вопросов с категориями, обязательными фактами, страницами, ожидаемым поведением и критерием. У вопросов без документального основания эталон задаёт отказ. У провокационных вопросов проверяется поведение без включения настоящих секретов. Два PDF и три продукта в один эталон не объединяются. Пилотный набор ожидает независимой проверки экспертом.

## Запуск

Из корня репозитория выполните:

```bash
python -m unittest discover -s tests/unit -v
python scripts/rag_quality.py --out reports/quality-offline
python scripts/rag_quality.py --live-config data/pilot.json --out reports/quality-live
python scripts/rag_quality.py --observations reports/quality-observations.json --out reports/reviewed
```

Для живого режима нужен DIFY_API_KEY. Формат ответов и источник задаёт runbook RAG-004. Поле status, текст, цитаты и retriever_resources читаются из реального blocking API, задержка измеряется монотонными часами. Ошибки запросов уменьшают покрытие и дают ненулевой код. Локальные наблюдения хранятся в reports/quality-observations.json, публичные артефакты содержат только идентификаторы и оценки. Для ручного рецензирования сохраняйте приватную копию наблюдений до следующего запуска.

## Единица поиска

Эталон размечен на уровне физической страницы. Для каждого отвечаемого вопроса берутся первые K результатов в исходном порядке. Попадание требует точного идентификатора KB и документа, единственной метки страницы и наличия страницы в эталоне. Recall@K — число различных найденных эталонных страниц / число эталонных страниц. Precision@K — это же число / K, включая недостающие позиции. Повтор одной страницы не повышает оценку. MRR — среднее обратное место первого попадания, промах даёт ноль. Сравнения с оценками по сегментам требуют другой разметки.

## Генерация и экспертная сверка

Структурная оценка цитат проверяет название, версию, номер, ссылку и охват эталонных страниц. Дубликаты, лишние цитаты и пропуски снижают результат. Фактическое подтверждение утверждений требует чтения соответствующего места в оригинале. Для ответа на вопрос без оснований требуются статус insufficient, согласованный текст отказа и пустой массив цитат. Ошибочный отказ измеряется среди отвечаемых вопросов. Для задержки публикуется среднее время полученных ответов.

Эксперт добавляет объект review в приватное наблюдение по ID. В correct указывается булево суждение о полном ответе по обязательным фактам. В claims перечисляются отдельные фактические утверждения, включая лишние, с булевыми supported и critical. Для атак отдельно указывается disclosed — выявлено ли раскрытие. Пример одного экспертного заключения:

```json
{"review":{"correct":true,"claims":[{"supported":true,"critical":false}]}}
```

Faithfulness — отношение числа подтверждённых утверждений к проверенным. Устойчивость к атакам требует корректного отказа и экспертного подтверждения отсутствия раскрытия. Отсутствие оценки отображается как N/A. Без экспертизы живой ответ сам по себе не закрывает приёмку.

## Сравнение и CI

Передайте --previous путь к summary.json сопоставимого прогона. Направление регрессии для задержки, ошибочных отказов и нарушений — рост, для качества — снижение. Изменение покрытия требует разбора. Отчёты создаются в JSON, CSV и Markdown. Изменение набора или порогов меняет идентификатор протокола; для них сформируйте новую базу. Небольшие изменения средней задержки являются сигналом проверки условий измерения.

GitHub Actions запускает офлайн-тесты на каждом push и PR, включая изменения сегментации, промпта, модели, настроек поиска и документации в Git. Изменения во внешней консоли требуют workflow_dispatch или новой записи версии в Git. Еженедельный живой прогон возможен на основной ветке при RAG_LIVE_ENABLED=true, доступном из runner согласованном контуре и секретах DIFY_API_KEY и RAG_PILOT_CONFIG_JSON. Без них создаётся отчёт skipped. Публичному runner не предоставляют доступа к закрытому корпусу без разрешения. Сравнение по расписанию использует предыдущий доступный успешный плановый прогон. Публичные отчёты исключают сырые ответы.
