# Тестовый стенд

## Подготовка и запуск

Нужны Git, Python 3.13, Docker Engine или Docker Desktop с Linux-контейнерами и Compose v2 с поддержкой !override (проверена 2.40.3). Команды выполняются из корня клона. Используйте отдельное имя проекта rag-pilot и отдельные БД. Скрипт сохраняет upstream, данные и конфигурацию в исключённом из Git каталоге data/stand.

| Операция | Linux | Windows PowerShell |
| --- | --- | --- |
| Диагностика | python3 scripts/diagnose_stand.py | py -3.13 scripts/diagnose_stand.py |
| Скачать и проверить закреплённую ревизию, создать случайные внутренние ключи | bash infra/dify/install-linux.sh prepare | ./infra/dify/install-windows.ps1 prepare |
| Проверить состав Compose | bash infra/dify/install-linux.sh check | ./infra/dify/install-windows.ps1 check |
| Запустить после заполнения .env | bash infra/dify/install-linux.sh start | ./infra/dify/install-windows.ps1 start |

1. В data/stand/.env задайте частные адреса и учётные данные Postgres Pro (две базы dify и dify_plugin), Platform V и одобренного Redis-совместимого сервиса для кэша и Celery. CELERY_BROKER_URL должен вести в тот же согласованный контур. Для Postgres Pro проверьте version(), наличие uuid-ossp, права миграции схемы, транзакции, резервирование и восстановление. Векторный индекс находится в Platform V. Режим VECTOR_STORE=qdrant обозначает протокол коннектора. Встроенные серверы PostgreSQL, Redis и Qdrant не входят в список запуска.
2. Проверьте выход контейнеров к частным адресам, доверенные корневые сертификаты, допуск отправки текста провайдеру и доступное место для образов и томов. Конфигурация публикует только nginx на loopback:8080. Доступ пользователей организуйте внутри защищённого контура через аутентифицированный TLS-вход. Не выставляйте начальный мастер установки в интернет.
3. После start откройте http://127.0.0.1:8080/install с сервера или через разрешённый туннель. Создайте администратора и один workspace, установите одобренный провайдер. На синтетических данных проверьте генерацию GigaChat, эмбеддинги и поиск Platform V с фильтрами. Сохраните версии и результаты. Если компонент не прошёл проверку, загрузку PDF отложите.
4. Выпустите в консоли ключ Knowledge API, предоставьте его процессу как DIFY_KNOWLEDGE_API_KEY. Укажите DIFY_BASE_URL (HTTPS URL с /v1), EMBEDDING_PROVIDER и EMBEDDING_MODEL (точные идентификаторы проверенного российского провайдера), PILOT_PDF_URL. Шаблон приложения находится в configs/pilot.example.json. Не включайте вывод переменных и HTTP-заголовков в логи.
5. Подготовьте пакеты по [пилотному runbook](pilot-runbook.md). Для автоматического варианта используйте следующую команду вместо ручного импорта. Она создаёт частную KB и один документ из извлечённого и проверенного текста, проверяет все активные сегменты, страницы и содержимое, затем записывает конфигурацию. Оригинал PDF остаётся в data/raw и в согласованном закрытом хранилище ссылок. Запускайте один импорт за раз. При сбое повторите команду после проверки состояния на сервере.

```bash
python3 scripts/provision_pilot.py data/processed/pilot-batches --config-out data/pilot.json
```

6. Создайте Chatflow с единственным узлом поиска по этой KB, включите возврат retriever_resources, настройте формат ответа по пилотному runbook и опубликуйте приложение внутри закрытой сети. Выдайте DIFY_API_KEY через окружение. Запустите проверку и приложите обезличенную сводку и ручную сверку ссылок.

```bash
python3 scripts/check_pilot.py --preflight --config data/pilot.json
python3 scripts/check_pilot.py --config data/pilot.json --report reports/pilot-run.json
```

На Windows для команд Python используйте py -3.13. Реальный отчёт содержит ответы и ссылки и остаётся в reports/. Для остановки используйте docker compose -p rag-pilot с теми же --env-file и двумя -f, что в scripts/install_stand.py, затем stop. Сохраните тома, базы и ключи для повторного запуска.

## Происхождение, лицензии и риски

| Компонент | Основание выбора и границы проверки |
| --- | --- |
| Dify API/Web 1.9.2, LangGenius | Иностранная платформа. Для изолированного теста закреплена конкретная ревизия с проверенным Compose и API. Лицензия на этой ревизии модифицирует Apache 2.0, ограничивает многопользовательский сервис с несколькими workspace и изменение брендинга. До эксплуатации требуется ревью обновлений и безопасности. [Лицензия](https://github.com/langgenius/dify/blob/ec871819e46de82f2f9ee33a71a61d96a58bdb37/LICENSE) |
| Plugin daemon 0.3.3-local, sandbox 0.2.12, nginx и Squid | Вспомогательное иностранное ПО. Nginx и образ Ubuntu/Squid зафиксированы по digest. Условия конкретных пакетов и транзитивных компонентов в образах требуют проверки SBOM и notices перед внедрением. Полная аттестация происхождения остаётся открытой. |
| GigaChat и GigaChat Embeddings | Российские сервисы, доступ и объёмы определяет корпоративное соглашение. Нужна совместимая версия провайдера Dify с поддержкой обеих операций. [Условия](https://developers.sber.ru/docs/ru/policies/gigachat-agreement/general) |
| YandexGPT и эмбеддинги Yandex Cloud | Альтернатива требует согласования, прав на сервисный аккаунт, папку и использование тарифа. Совместимость в этом стенде не установлена. [Документация](https://yandex.cloud/ru/docs/foundation-models/) |
| Postgres Pro | Российский продукт Postgres Professional. Проверять условия конкретной сборки. Trial разрешён для тестирования с ограничениями, коммерческая поставка требует соответствующих прав. Исходная миграция Dify использует uuid-ossp. [Условия сборок](https://postgrespro.ru/docs/postgrespro/17/trial-builds) |
| Platform V Vector DB | Российская поставка СберТех на базе Qdrant. Нужны доступ к дистрибутиву или экземпляру, лицензия и проверка совместимости API и фильтров. Происхождение каждого алгоритма требует отдельной оценки. [Установка](https://platformv.sbertech.ru/docs/public/VDB/2.0.0/common/documents/installation-guide/installation.html) |
| Кэш и брокер | Требуется согласованный российский Redis-совместимый сервис с поддержкой команд Dify и Celery. Общая совместимость протокола и лицензия конкретной поставки остаются открытыми. |

Долговечность тома проверена между контейнерами одного демона. Для данных пилота требуется отдельно проверить сохранность после пересоздания облачной среды, резервную копию и восстановление.

## Результаты испытаний

- **Выполнено и проверено.** Debian 13.7, 3 видимых CPU (квота 2), 9,7 GiB RAM хоста (лимит 8 GiB), изначально свободно 7,5 GiB. В обычной песочнице сокеты и Docker недоступны. При сетевом разрешении Engine 29.9.2 запустил hello-world, реестр Docker предоставил образы, PyPI предоставил wheel, тестовые HTTP-запросы прошли. Том busybox сохранил значение между контейнерами. Отдельный контейнер Dify Web 1.9.2 отдал HTTP 200 для /install и затем был остановлен. Публичный вход не создавался.
- **Реализовано, но не проверено на реальном стенде.** Установщики, Compose для внешних сервисов, автоматизация KB и сверка 363 сегментов. На HTTP-заглушке проверены создание, пагинация, возобновление и обнаружение изменения текста. CI использует только синтетические данные.
- **Заблокировано.** Полный старт, генерация и эмбеддинги, проверка миграций, авторизации и поиска в согласованных БД. Нужны доступы из таблицы выше. Отдельно требуется проверка жизненного цикла томов на целевой Windows 11 / WSL 2.
- **Не начато на живом стенде.** Индексация документа, три вопроса, проверка цитат и переходов в Web Chat. [Машиночитаемый результат](stand-test-results.json)
