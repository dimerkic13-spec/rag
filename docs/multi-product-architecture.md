# Изоляция трёх продуктов

Размещать оригиналы под data/raw/{product}/{product_version}/{document}/{document_version}/, результаты — в аналогичном поддереве data/processed/. Идентификаторы выдаёт реестр, имена путей не берутся из пользовательского вопроса. Для исходного PDF хранить SHA-256 байтов. Ключ страницы состоит из четырёх идентификаторов, checksum и физического номера страницы. Для сегмента дополнительно сохранять номер сегмента и название раздела. indexed_at содержит дату и часовой пояс. Поле allowed_groups задаёт ACL документа; пустой список закрывает доступ.

Исполняемая схема Page и проверка visible находятся в src/quality/scope.py. Сервер получает группы из проверенной пользовательской сессии и выбирает активную ревизию из доверенного реестра. Точные ограничения по продукту, версии, ACL и активным ревизиям применяются до поиска и повторно к каждому результату перед генерацией. Неизвестная ревизия или контрольная сумма закрывает доступ. У ответа должны быть источники в пределах разрешённого контекста. Для общего поиска отдельно формируются допустимые области по каждому продукту; объединение результатов сохраняет принадлежность документа и версии. Ключ кэша должен включать область доступа и ревизию корпуса.

При обновлении сначала построить отдельную версию индекса, проверить её и атомарно переключить активное отображение реестра. Старая версия доступна только при явно выбранной разрешённой исторической ревизии. Для продуктов 2 и 3 материалы и политики групп ещё нужны. Реализованная проверка протестирована на синтетике; подключение фильтров к выбранному Dify/vector backend и end-to-end проверка утечки между продуктами остаются открытыми.
